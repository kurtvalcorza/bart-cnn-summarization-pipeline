# Release verification

`tutorials/bart_summarization_colab.ipynb` (`E2E`, **standalone** carrier) is a **release candidate** until the
exact notebook revision has executed top-to-bottom, in one pass, in a clean supported runtime. Unit tests, JSON
validation, code-cell compilation, the generator parity checks and `tools/validate_release_assets.py` are necessary
checks but are **not** runtime evidence under DIMER Notebook Specification 2.2 (REL8). This file is the durable
release-gate record for the notebook.

Since the fix of review findings BART-M1..M5 / BART-m1..m7 (Notebook Review Framework v1, review PR #8) the notebook
is generated by `tools/build_notebook.py` /3: nothing is installed into the notebook kernel, a pinned `uv` builds an
isolated CPython 3.12.12 environment from `tutorials/requirements-colab.lock.txt` with `--require-hashes`, and every
learner cell runs one stage of the carried `tools/tutorial_stages.py` in its own process. The procedure below
describes that notebook; the recorded executions further down are of the previous, in-kernel version and say so,
except the local pre-flight row of the current version, which is not promotion evidence, and the hosted Colab T4 run
of the current blob recorded on 2026-10-03.

## Automatic coverage (static, every pull request)

CI runs `tools/validate_release_assets.py`, which checks:

- notebook JSON parses; every code cell compiles as plain Python (no `%`/`!` magics); no persisted outputs or
  execution counts; no unresolved placeholder markers; every code cell is preceded by an explanatory markdown cell;
- exactly one tutorial notebook, named in `tutorials/README.md` with its `E2E` profile, the notebook-spec version,
  the standalone carrier and the isolated environment; `metadata.dimer` declares that profile, spec `2.2`, a §3.3
  pedagogical mode, `standalone: true`, `requires_dimer_worker: false` and `generated_from` (repository, revision,
  module SHA-256, file digests, generator);
- the standalone carrier (ST1–ST8, SRC4, PAR1–PAR4): exactly one carrier cell whose `CARRIED_FILES` equal the
  repository files (the 4 package files, the stage runner, the lock, the snapshot manifest, the licence and
  `source.json`) and whose `CARRIED_HASHES` are correct, verified in the cell before use; the notebook byte-identical
  (on LF) to the generator output for its recorded revision;
- the isolated install (RUN10, ENV6): the lock pins every `pyproject.toml` pin with hashes and was compiled
  wheel-only for manylinux x86_64; the `uv` wheel is pinned by URL, size and SHA-256; the only installer call is
  `uv pip install --python <isolated env> --require-hashes`; no kernel cell imports a model library, `importlib` or
  `pickle` or runs `pip`; `run_stage` re-raises a stage's own error message;
- the canonical stages called exactly once each in order (`weights`, `runtime`, `data`, `inference`, `frozen`,
  `adapt`, `evaluate`, `new`, `reload`, `bundle`, then the optional `activity`), the BYOD fields `USE_BYOD` /
  `BYOD_PATH` driving the `data` stage in one cell, the stage runner's required public-API calls, checks and refusals
  (the workflow minimum, the token-ceiling check, the de-duplication count, the count-based truncation check, the
  frozen-pipeline check, the default-path expectation, the decoder-tensor reload parity, the provenance fields
  `weight_format`, `remote_code_executed: False` and the `corpus` block) and the expected outputs;
- the guided layer (GDL1–GDL15): how to use, the input → model → output table, roadmap, fast path, glossary, section
  tags on every numbered heading, minimum counts of prediction prompts, notes, expected results and collapsed answers,
  the optional activity gated off and placed after the canonical path, troubleshooting, the conclusion template, and
  titled, collapsed infrastructure cells; no learner prose instructs a runtime restart, no timing is stated without
  its environment, no markdown shows doubled braces, and no learner cell or stage asserts a result;
- `MODEL_ID`/`MODEL_REVISION` bound only in the carried package, the revision a 40-hex immutable commit, and the
  same identity string in `README.md`, `MODEL_CARD.md` and `docs/WEIGHTS.md` with no stray revisions (the pinned
  `allenai/scitldr` corpus commit is the one allowed second hash);
- forbidden patterns (credential-in-URL, any `git clone` / `github.com` / repository import on the primary path, a
  mutable `revision='main'`, `trust_remote_code=True`, `pickle.load` or `torch.load(` without `weights_only=True`,
  `extractall(`, source or unhashed installs) in the kernel cells and the carried files;
- `STATUS.md`, `README.md` and `tutorials/README.md` agree on one release-status token and no document makes an
  unsupported release-grade, production-readiness or benchmark claim;
- `MODEL_CARD.md` front matter (`model_card_spec: "1.1"`), single H1, the 19 required headings in order, and the
  immutable provenance section.

CI also runs `ruff check src tests tools`, `tools/build_notebook.py --check`, and the offline unit suite (injected
runner, token counter and corpus fetcher, temporary manifests; no weights, no `torch` and no `transformers` — the
stand-in-model tests in `tests/test_bart_summarization_colab_review_fixes.py` and `tests/test_model_backed.py` are
skipped there). These are source/provenance and unit checks. They are **not** execution evidence.

## Executor paths

| Path | Runtime | Role |
|---|---|---|
| Google Colab (supported user path) | Colab CPU or T4 runtime (CUDA used automatically when present); the stages run in the notebook's isolated CPython 3.12.12 environment | The runtime the tutorial is written for; a clean one-pass top-to-bottom run here is promotion evidence |
| Kaggle CLI kernel or equivalent fresh container | Fresh Linux x86_64 CPU or GPU container; the committed notebook executed verbatim in a fresh interpreter with **no repository checkout** (the notebook is standalone) | Reproducible clean-room executor of the same class; promotion evidence when the run is one pass |
| Local harness (pre-flight only) | Workstation; the learner stages run with a local venv of the pinned versions standing in for the isolated environment | Builder pre-flight to catch defects before spending cloud runs; **not** a supported runtime and **not** promotion evidence |

## Supported release verification procedure

Before changing the registry status from `Candidate` to `Release-grade`:

1. resolve the exact PR/commit head under review and confirm static CI is green;
2. open that exact notebook revision in a new Linux x86_64 CPU or CUDA runtime (Colab, or a fresh-container
   executor above) with **no repository checkout**, an empty Hugging Face cache, and no pre-staged files under the
   working-directory snapshot `weights/bart-large-cnn/` or the corpus cache `weights/scitldr/` (the standalone path
   writes the manifest itself, stages the missing files from the Hub, and fetches the three pinned SciTLDR-A files
   from the project repository, so neither directory may be seeded);
3. choose **Run all once** without editing implementation cells (form parameters at their defaults:
   `USE_BYOD = False`, `BYOD_PATH = ''`, `SPLIT_SEED = 42`, `TLDR_MAX_NEW_TOKENS = 48`, `TLDR_MIN_NEW_TOKENS = 0`,
   `NUM_BEAMS = 4`, `EPOCHS = 2`, `LEARNING_RATE = 3e-5`, `BATCH_SIZE = 8`, `TRAINABLE_DECODER_LAYERS = 2`,
   `RUN_ACTIVITY = False`). **The run must complete in one pass**: a restart of the interpreter, a second pass or a
   manual re-run of any cell means the run is not `Run all` evidence (RUN1, RUN10) — record it with its pass count,
   never as PASSED;
4. verify that Section 2 reports the carried files verified and the revision recorded in
   `metadata.dimer.generated_from`, that the isolated environment reports CPython 3.12.12, and that Section 4 reports
   `versions_match_lock: True` for `torch==2.14.0`, `transformers==4.57.6`, `tokenizers==0.22.2`,
   `safetensors==0.8.0`, `huggingface-hub==0.36.2` and `numpy==2.5.3`;
5. verify every default-path stage completes:
   - Section 3: `model.safetensors` (and any other absent manifest entry) fetched from `facebook/bart-large-cnn` at
     the immutable revision, and `verified_files: 8`;
   - Section 5: the three pinned files (3,155,015 / 1,124,865 / 1,204,107 bytes) fetched into `weights/scitldr/`,
     1,992 + 619 + 618 raw papers, splits 300 / 50 / 100 with `check_split_disjoint` clean and the dataset digests
     `1ecede32…` / `4693cd21…` / `55db9c45…` (the training digest the Kaggle run printed; an earlier version of this
     file quoted `5fc73d14…` from a pre-flight of another revision), 4 new documents, the per-split token maxima
     (all below 1,024), and five refusal probes (duplicate id, empty reference list, missing field, too few for this
     workflow, an over-long test source);
   - Section 6: the input manifest with one recorded `num_beams` rejection; the synthetic document summarised under
     the pinned defaults (81 content tokens, `stopped_by: eos` in the recorded runs) and under the TL;DR settings
     (46 content tokens = the 48-token cap minus the forced start and end tokens, `truncated: True`,
     `stopped_by: max_new_tokens`), with every sanity check `True`;
   - Section 7: Lead-1 and Lead-3 (ROUGE-L 23.61 / 19.86 on the sample), the frozen model's test scores
     (ROUGE-1/2/L ≈ 33.5 / 14.7 / 25.5 at ≈ 35 words) with `adapted: False`, and the count of frozen summaries cut at
     the cap;
   - Section 8: `adapted: False` at the start, epoch 0 as the frozen model, 33,593,344 trainable of 406,290,432
     parameters, a two-epoch history with validation ROUGE-L rising, and the adapter (52 tensors, about 134 MB);
   - Section 9: the four-way comparison with the adapter rebuilt from files and the outcome line (adapted ROUGE-L
     ≈ 33.6 on a T4 and ≈ 34.3 on CPU against ≈ 25.5 frozen in the recorded runs; the stage stops if the default
     configuration does not improve);
   - Section 10: four unseen dev abstracts summarised, a `measured-small-sample` verdict and a `sample-sanity`
     single-document report;
   - Section 11: `decoder_tensors_identical: True`, 4/4 identical summaries, `reload_verification: PASSED`;
   - Section 12: `outputs/bart_summarization/<run id>/outputs/bart_summarization_result.json` with the provenance
     blocks and the SHA-256 of every output;
6. verify the exports exist and the interpretation section matches the observed path; for the optional journeys,
   run the activity (`RUN_ACTIVITY = True`), one BYOD positive run (for example the Section 5 training CSV as
   `BYOD_PATH`), and one BYOD negative run (a file with fewer than 12 distinct sources, refused in Section 5), and
   record each;
7. record the notebook Git blob id, commit, runtime (platform, kernel Python, isolated-environment Python, PyTorch,
   Transformers, device), the model identifier and immutable revision, whether the caches were clean, the pass count,
   outcome, produced outputs, the observed metrics (as observations, not a benchmark) and any warning or applicable
   `SHOULD` deviation in the tables below;
8. record no access tokens or other secrets.

A known-failing default path in the supported runtime blocks release (REL11).
