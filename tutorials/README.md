## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) summarised one synthetic passage and reported a `not-measurable` verdict because the repository shipped no metric and the sample had no reference. This notebook keeps that inference contract as Section 5 and adds the adaptation contract around it: a real referenced corpus chosen because it is out of the model's domain, three ROUGE metrics implemented in the carried `metrics.py`, two Lead baselines, explicit TL;DR-length generation settings applied identically to the frozen and the adapted model, a bounded fine-tuning, and an artifact that reloads. `evaluation_report` now scores supplied references for one document (`sample-sanity`) and still returns `not-measurable` without them; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 8-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry; `BARTSummarizationPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`); no cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors` or `urllib`.
- **Data (DAT1–DAT9, ST6):** the default sample is three pinned objects — `train.jsonl` / `dev.jsonl` / `test.jsonl` of SciTLDR-A (3,155,015 / 1,124,865 / 1,204,107 bytes; SHA-256 `b222771d…` / `3191fa98…` / `fb42dd6c…`) from `raw.githubusercontent.com` at the pinned `allenai/scitldr` commit — each refused on any mismatch before it is parsed, filtered to abstracts of 200..2,400 characters with at least one reference and de-duplicated on the source, and drawn by a seeded shuffle into 300 / 50 / 100 records from the release's own paper-disjoint members (`check_split_disjoint` asserts it). The template adds a second *External access* bullet naming the host, the byte counts and the Apache-2.0 licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + refusal probes (validation, with three digests) → `validate_inputs` + `pipe.summarize` with sanity checks under the pinned defaults and the TL;DR settings (inference contract) → `lead_baseline` ×2 + `pipe.evaluate` on the frozen model (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.summarize` on unseen abstracts + `pipe.evaluate` + `evaluation_report` (inference) → `pipe.save_artifact` → `BARTSummarizationPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the pipeline emits no probability, confidence or score; ROUGE-1/2/L are corpus-level n-gram agreement with references (own implementations, best over the references, rouge-score-style, not rouge-score-identical, no stemming, no faithfulness); no acceptance threshold ships, and `truncated` is a length flag. Four unseen abstracts are scored with a `measured-small-sample` verdict that names the missing dispersion.
- **Length control (EVAL6/EVAL10/EVAL11):** the frozen model's pinned defaults force at least 55 new tokens, so every ROUGE number is produced under explicit TL;DR-length settings (`max_new_tokens` 48, `min_new_tokens` 0, `num_beams` 4) applied identically to the Lead baselines, the frozen model and the adapted model on the same 100 test abstracts; `mean_summary_words` and `mean_reference_words` are printed beside every score, and every metric is labelled as one seeded split of one corpus with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** the split is seeded and source-disjoint (the release's own train/dev/test partition); validation selects the epoch and the test split is used for nothing but the final evaluation; the notebook states that pairs from one document collection or author must be split by that grouping.
- **Ceilings (VAL6):** `MAX_TEXT_CHARS` (40,000), `MAX_INPUT_TOKENS` (1,024, rejected not truncated or chunked), `MAX_NEW_TOKENS` (512), `MAX_NUM_BEAMS` (8), `LENGTH_PENALTY_RANGE`, `MAX_NO_REPEAT_NGRAM_SIZE` (10), the record bounds (8..20,000), the reference ceiling (2,000 characters), the id pattern and the training-only 512/64-token truncation are stated in the Prerequisites and printed before the model runs; four dataset refusals and one settings refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user pairs flow through the same validation, seeded source-disjoint split, baselines, fine-tuning, evaluation, inference, export and reload cells. The expected schema and the privacy guidance — an internal report archive with its executive summaries is restricted data — are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/bart_summarization_train.csv` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
