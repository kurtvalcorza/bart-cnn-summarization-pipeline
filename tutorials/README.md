## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) summarised one synthetic passage and reported a `not-measurable` verdict because the repository shipped no metric and the sample had no reference. This notebook keeps that inference contract as Section 6 and adds the adaptation contract around it: a real referenced corpus chosen because it is out of the model's domain, three ROUGE metrics implemented in the carried `metrics.py`, two Lead baselines, explicit TL;DR-length generation settings applied identically to the frozen and the adapted model, a bounded fine-tuning, and an artifact that reloads. `evaluation_report` now scores supplied references for one document (`sample-sanity`) and still returns `not-measurable` without them; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8, SRC4):** the primary path performs no clone, repository install, or repository import. Section 2 carries `src/bart_summarization_pipeline/` (4 files), `tutorial_stages.py`, `requirements.txt` (the lock), the 8-file snapshot manifest, the licence and `source.json`; each is written to a fresh run directory and verified against `CARRIED_HASHES` before use, and `source.json` records the repository, revision and file digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried file differs from the repository, when the lock does not pin every `pyproject.toml` pin with hashes, or when the notebook is not byte-identical to the generator's output.
- **One-pass Run all (RUN1, RUN10, ENV6):** nothing is installed into the kernel; the pinned `uv` wheel is checked by size and SHA-256, builds a managed CPython 3.12.12 venv and installs the lock with `--require-hashes --only-binary :all:`; the `runtime` stage refuses a version that differs from the lock.
- **Model acquisition (MOD1–MOD9):** the `weights` stage fetches only the manifest entries that are absent (the git-ignored `model.safetensors` on a fresh runtime), from the Hugging Face Hub at the immutable revision (never `main`), and re-hashes every entry; every model stage loads the verified files with `local_files_only=True` and `trust_remote_code=False`; no kernel cell imports `torch`, `transformers`, `safetensors` or `huggingface_hub`.
- **Data (DAT1–DAT19, ST6):** the default sample is three pinned objects — `train.jsonl` / `dev.jsonl` / `test.jsonl` of SciTLDR-A (3,155,015 / 1,124,865 / 1,204,107 bytes; SHA-256 `b222771d…` / `3191fa98…` / `fb42dd6c…`) from `raw.githubusercontent.com` at the pinned `allenai/scitldr` commit — each refused on any mismatch before it is parsed, filtered to abstracts of 200..2,400 characters with at least one reference and de-duplicated on the source, and drawn by a seeded shuffle into 300 / 50 / 100 records from the release's own paper-disjoint members (`check_split_disjoint` asserts it), plus four `dev` abstracts in none of the splits for Section 10. Pretraining overlap with BART's training text cannot be ruled out and is stated.
- **Stages (§4.1):** `data` (sample or BYOD, `validate_dataset` per split, the workflow minimum and the token ceiling, `check_split_disjoint`, training CSV, five refusal probes) → `inference` (`validate_inputs` + `summarize` under the pinned defaults and the TL;DR settings, with a count-based truncation check) → `frozen` (`lead_baseline` ×2 + frozen `evaluate`, written before adaptation) → `adapt` (fresh frozen pipeline, bounded fine-tuning, adapter export) → `evaluate` (adapter rebuilt from files; four-way comparison) → `new` (four documents, `evaluate` + `evaluation_report`) → `reload` (fresh process; decoder-tensor and summary parity) → `bundle`; optional `activity`.
- **Reruns start from the frozen model (DAT13, DAT14, UX7):** each stage that runs the model builds it from the verified files in its own process; `BARTSummarizationPipeline.adapt` refuses an already-adapted pipeline; re-running a section clears every later result computed from its inputs, and a later stage refuses an adapter trained on other data or generation settings.
- **Score semantics (UNC1–UNC4, INF3):** the pipeline emits no probability, confidence or score; ROUGE-1/2/L are corpus-level n-gram agreement with references (own implementations, best over the references, rouge-score-style, not rouge-score-identical, no stemming, no faithfulness); no acceptance threshold ships, and `truncated` is a length flag decided from the length, because the pinned config forces an end token at the cap. Four new documents are scored with a `measured-small-sample` verdict that names the missing dispersion.
- **Length control (EVAL6/EVAL10/EVAL11):** the frozen model's pinned defaults force at least 55 new tokens, so every model ROUGE number is produced under explicit TL;DR-length settings (`max_new_tokens` 48, `min_new_tokens` 0, `num_beams` 4) applied identically to the frozen and the adapted model on the same 100 test abstracts. The Lead baselines copy sentences and take no generation settings; `mean_summary_words`, `mean_reference_words` and the number of summaries cut at the cap are printed beside every score, and every metric is labelled as one seeded split of one corpus with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** the split is seeded and source-disjoint (the release's own train/dev/test partition); validation selects the epoch and the test split is used for nothing but evaluation; the notebook states that pairs from one document collection or author must be split by that grouping.
- **Ceilings (VAL1, VAL6, VAL7):** `MAX_TEXT_CHARS` (40,000), `MAX_INPUT_TOKENS` (1,024, rejected not truncated or chunked — checked for every validation, test and Section 10 source in Section 5, before any model runs), `MAX_NEW_TOKENS` (512), `MAX_NUM_BEAMS` (8), `LENGTH_PENALTY_RANGE`, `MAX_NO_REPEAT_NGRAM_SIZE` (10), the package's record bounds (8..20,000) and this workflow's minimum (12 records with distinct sources), the reference ceiling (2,000 characters), the id pattern and the training-only 512/64-token truncation are stated in the Prerequisites and enforced before the model runs; five dataset refusals and one settings refusal are demonstrated.
- **BYOD (DAT10–DAT19, EXE1, EXE2):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; `BYOD_PATH` reads a file on any runtime, and the Colab upload dialog is used only when it is empty (an empty upload names the fix). User pairs are de-duplicated (the count is printed), split 15 % / 20 % / rest and flow through the same baselines, fine-tuning, evaluation, inference, export and reload stages; Section 10 says that its documents are BYOD test records. The privacy guidance — an internal report archive with its executive summaries is restricted data — is stated in the Prerequisites, and the training split is written to `bart_summarization_train.csv` in the run's `outputs/` directory in the BYOD shape.
- **Guided layer (GDL1–GDL15):** how to use, the input → model → output table, roadmap, fast path, glossary, section tags, prediction prompts, collapsed "Check your reasoning" answers, an optional Predict → Change one thing → Run → Observe → Explain activity (the summary-length cap, off by default, writing only under `outputs/activity/`), troubleshooting and a conclusion template; infrastructure cells are titled and collapsed.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded one-pass clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
